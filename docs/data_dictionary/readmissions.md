## readmissions.encounter_augmented

- **dbt model:** `readmissions__encounter_augmented`
- **Grain:** _not declared_
- **Materialization:** table
- **Description:** This model includes all encounters from the stg_encounter model, and for each encounter_id we add fields relevant for the encounter.

| Column | Type | Key / Tests | Description |
|---|---|---|---|
| `encounter_id` |  |  | The unique identifier for the encounter |
| `person_id` |  |  | The unique identifier for the patient |
| `admit_date` |  |  | The date of admission for the inpatient visit |
| `discharge_date` |  |  | The date of discharge for the inpatient visit |
| `discharge_disposition_code` |  |  | The valid 2-digit discharge status for the inpatient visit |
| `facility_id` |  |  | An ID for the facility where the inpatient visit occurred |
| `ms_drg_code` |  |  | The MS-DRG associted with the inpatient visit |
| `paid_amount` |  |  | The number of dollars paid on the encounter |
| `length_of_stay` | integer |  | Integer representing the length of stay of the inpatient visit in days |
| `index_admission_flag` | boolean |  | Flag to indicate if the encounter is an index admission |
| `planned_flag` | boolean |  | Flag to indicate if the encounter was planned |
| `specialty_cohort` |  |  | Specialty cohort the encounter belongs to |
| `died_flag` | boolean |  | Flag to indicate of the patient died in this encounter |
| `diagnosis_ccs` |  |  | CCS code associated with the primary diagnosis for the encounter |
| `disqualified_encounter_flag` | boolean |  | A flag that indicates whether this encounter is disqualified from being used in readmission measures for any critical data quality problem. |
| `missing_admit_date_flag` | boolean |  | A flag that indicates whether the admit date is missing from this encounter. |
| `missing_discharge_date_flag` | boolean |  | A flag that indicates whether the discharge date is missing from this encounter. |
| `admit_after_discharge_flag` | boolean |  | A flag that indicates whether the admit date for the encounter is after the discharge date for the encounter. |
| `missing_discharge_disposition_code_flag` | boolean |  | A flag that indicates whether the discharge status code is missing for the encounter. |
| `invalid_discharge_disposition_code_flag` | boolean |  | A flag that indicates whether the discharge status code that is present for this encounter is invalid. This flag is 1 only when the discharge status code is present but invalid. |
| `missing_primary_diagnosis_flag` | boolean |  | A flag that indicates whether there is no primary diagnosis associated with the encounter. |
| `multiple_primary_diagnoses_flag` | boolean |  | A flag that indicates whether there are multiple primary diagnoses associated with the encounter. |
| `invalid_primary_diagnosis_code_flag` | boolean |  | A flag that indicates whether the primary diagnosis present for this encounter is invalid, i.e. a non existing ICD-10-CM code. This flag indicates that a primary diagnosis code is indeed present for the encounter, but it is not a valid ICD-10-CM code. |
| `no_diagnosis_ccs_flag` | boolean |  | A flag that indicates whether there is no CCS diagnosis category associated with the primary ICD-10-CM diagnosis code for the encounter. This flag indicates that there is a valid primary ICD-10-CM diagnosis code associated with the encounter, but there is no CCS diagnosis category associated with that ICD-10-CM code. |
| `overlaps_with_another_encounter_flag` | boolean |  | A flag that indicates whether this encounter's dates overlap with those of another encounter in the dataset |
| `missing_ms_drg_flag` | boolean |  | A flag that indicates whether this encounter contains a claim with a missing ms-drg code |
| `invalid_ms_drg_flag` | boolean |  | A flag that indicates whether this encounter contains a claim with an invalid missing ms-drg code |
| `tuva_last_run` |  |  | The time at with the model was materialized. Generated by `dbt_utils.pretty_time` as the local time of the `dbt run` environment. Timezone is configurable via the `tuva_last_run` var. |

## readmissions.readmission_summary

- **dbt model:** `readmissions__readmission_summary`
- **Grain:** _not declared_
- **Materialization:** table
- **Description:** This model includes all rows from the encounter_augmented model where disqualified_encounter_flag = 0 (all rows for encounters that are not disqualified for data quality issues). For each of these encounters we add fields to indicate whether it had a readmission and, when a readmission was present, to show relevant fields for the readmission.

|---|---|---|---|
| `encounter_id` |  |  | The unique identifier for the encounter |

| `discharge_disposition_code` |  |  | The valid 2-digit discharge status for the inpatient visit |
| `facility_id` |  |  | An ID for the facility where the inpatient visit occurred |
| `ms_drg_code` |  |  | The MS-DRG associted with the inpatient visit |
| `paid_amount` |  |  | The amount paid for the visit |
| `length_of_stay` | integer |  | Integer representing the length of stay of the inpatient visit in days |
| `index_admission_flag` | boolean |  | Flag to indicate if the encounter is an index admission |
| `planned_flag` | boolean |  | Flag to indicate if the encounter was planned |
| `specialty_cohort` |  |  | Specialty cohort the encounter belongs to |
| `died_flag` | boolean |  | Flag to indicate of the patient died in this encounter |
| `diagnosis_ccs` |  |  | CCS code associated with the primary diagnosis for the encounter |
| `had_readmission_flag` | boolean |  | A flag to indicate whether the encounter had a readmission any number of days after discharge |
| `days_to_readmit` | integer |  | An integer to indicate the number of days to readmission |
| `readmit_30_flag` | boolean |  | A flag to indicate whether the encounter had a 30-day readmission |

| `readmission_died_flag` | boolean |  | Flag to indicate of the patient died in the readmission encounter |
| `readmission_diagnosis_ccs` |  |  | CCS code associated with the primary diagnosis for the readmission encounter |
| `tuva_last_run` |  |  | The time at with the model was materialized. Generated by `dbt_utils.pretty_time` as the local time of the `dbt run` environment. Timezone is configurable via the `tuva_last_run` var. |
