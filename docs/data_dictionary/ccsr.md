## ccsr.long_condition_category

- **dbt model:** `ccsr__long_condition_category`
- **Grain:** _not declared_
- **Materialization:** table
- **Description:** This model contains a mapping of individual condition ICD-10-CM diagnosis codes to the CCSR's clinically meaningful diagnosis categories. Each row represents a mapping of an ICD-10 code to a CCSR category. As each ICD-10 code may be mapped to up to 6 categories, it's expected that this table will output as many or more rows than the TUVA condition model. The model is equivalent to the CCSR's Output Option 1 - Vertical File Output.

| Column | Type | Key / Tests | Description |
|---|---|---|---|
| `encounter_id` |  |  | Unique identifier for each the encounter. |
| `claim_id` |  |  | Unique identifier for each claim. |
| `person_id` |  |  | Unique identifier for each patient. |
| `normalized_code` |  |  | The ICD-10-CM code for the diagnosis. |
| `code_description` |  |  | The ICD-10-CM code description provided in the CCSR CSV seed file. |
| `condition_rank` | integer |  | The numerical ranking of a diagnosis code in a claim. |
| `body_system` |  |  | The body system to which each parent category belongs. The 22 body systems generally follow the structure of the ICD-10-CM diagnosis chapters. Note that the procedure tables don't have this column, but a conceptually related field in procedure models is `clinical_domain`. |
| `ccsr_parent_category` |  |  | The parent category code for each CCSR category. In practice, this is the three letter prefix to the category code. |
| `parent_category_description` |  |  | A description of the parent category. |
| `ccsr_category` |  |  | A CCSR category for the ICD-10-CM code. One ICD-10-CM code may have up 6 CCSR categories associated, ordinally ranked by the ccsr_category_rank. Will be null if a record has a `code` that isn't referenced in the CCSR seed file. |
| `ccsr_category_description` |  |  | The description of the CCSR category as provided in the CCSR seed file. |
| `ccsr_category_rank` |  |  | The ordinal rank of a given CCSR category mapped to an ICD-10-CM code. The CCSR seed CSV has the order of categories assigned to each ICD-10-CM code. |
| `is_ip_default_category` |  |  | For each ICD-10-CM code, this field will return true for the CCSR category that is the default value for the code if the underlying record is an inpatient encounter. |
| `is_op_default_category` |  |  | For each ICD-10-CM code, this field will return true for the CCSR category that is the default value for the code if the underlying record is an outpatient encounter. |
| `dxccsr_version` |  |  | The version number of the CCSR program from which the dbt model was derived. |
| `tuva_last_run` |  |  | The time at with the model was materialized. Generated by `dbt_utils.pretty_time` as the local time of the `dbt run` environment. Timezone is configurable via the `tuva_last_run` var. |

## ccsr.procedure_summary

- **dbt model:** `ccsr__procedure_summary`
- **Grain:** _not declared_
- **Materialization:** table
- **Description:** This table stores information on procedure volume patterns across CCSR categories.

| Column | Type | Key / Tests | Description |
|---|---|---|---|
| `ccsr_category` |  |  | The CCSR category mapped to the ICD-10-PCS code associated with the procedure |
| `ccsr_category_description` |  |  | A description of the clinical domain. |
| `operation` |  |  | The objective of the procedure performed |
| `approach` |  |  | The way the surgical site was reached |
| `n_occurrences_with_approach` |  |  | within a CCSR category, the number of times a specific approach occurred for a given operation. |
| `n_total_occurrences` |  |  | for a given CCSR category, the number of times specific operation occurred |
| `approach_rate` |  |  | Of all occurrences of an operation within a CCSR category, the rate at whiich a specific approach occurred. |
